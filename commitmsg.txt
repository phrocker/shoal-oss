tserver: close the second round of ServiceLock review findings

Maintain armed a fresh existence watch on every pass through its loop. A
ZooKeeper watch is one-shot but stays registered until it fires, so a
healthy lock accumulated one registration per verify interval for its
whole life and would have delivered all of them at once when the node
finally changed. One watch is now outstanding at a time, re-armed only
after the previous one is consumed; Verify remains the backstop that
re-reads the directory, so nothing is lost by not re-checking existence
on the timer path.

Release could report success in the window between an acquisition
checking the released flag and its create landing, leaving behind the
node the sweep existed to remove. The check-and-create and the sweep are
now mutually exclusive, so either the create happens and the sweep finds
it, or the release wins and there is no create at all.

Resource groups are held to Accumulo's ResourceGroupId grammar.
ServiceLockData.parse runs every descriptor's group through
ResourceGroupId.of, which throws outside that grammar, so a group this
process accepted and Accumulo did not made the whole znode unreadable to
the manager -- the same failure a non-canonical UUID causes, reached
through a different field. It also kept a traversal such as "../managers"
out of the lock path, which path.Join would otherwise have cleaned into
another role's subtree rather than rejected. TabletServerLockPath now
returns an error rather than a path it cannot vouch for.

TabletServerLockData accepted any service the enum defines, including
MANAGER, COORDINATOR and GC. Those belong to processes that implement
them and advertise them on their own locks; the tablet-server
constructor now takes only the five services a Java tablet server
publishes.

Participate promised that a rejoin always carries a higher sequence.
That is false across a lock directory being deleted and recreated --
ZooKeeper's counter lives on the parent, the same reset Verify reports as
LossSuperseded -- so a rejoin can be handed a generation the host has
already used and AdoptLock refuses it. The documentation now states the
recovery, a fresh Host, instead of a guarantee that does not hold.

Tests cover watch accounting across many verify intervals and re-arming
after a watch fires, a release racing a create in flight, the group
grammar at the descriptor, constructor and path layers, another role's
service being refused, and a rejoin into a recreated directory needing a
fresh host. The two race fixes were confirmed by reverting each in turn:
the watch test reports 21 outstanding watches, and the release test
reports a node registered behind a release that had already returned.

Nothing here decides placement. The added checks only refuse to publish
or register things Accumulo could not read; the manager remains the sole
authority for assignment, and this process still only registers presence
and observes the manager's own lock.
